DOCKER · 镜像与容器

同一镜像，
为什么是两个世界？

亲爱的主人，今天不背定义。我们只解决一个问题：从同一个镜像启动两个容器，在其中一个里改了文件，另一个会跟着改变吗？

约 5～8 分钟来自你的 2 个真实节点无需安装或运行 Docker

01 / 回想先凭直觉，选一次

用同一个镜像创建容器 A 和 B。你在 A 自身的文件系统里新建了 note.txt。

本节约定：没有共享目录、数据卷或程序主动同步；这里讨论的只是容器自身的文件修改。

B 会自动看到这个文件吗？

02 / 理解相同的起点，各自的改动

作答后展开：用一张关系图讲清楚

镜像提供创建容器所需的文件和配置。镜像创建后不能直接改写它的内容；需要更新时，产生的是新的镜像。[1]

容器是基于镜像创建的隔离运行环境。它不是镜像的新名字：运行时对自身文件系统的修改，放在自己的可写层里。[2] [3]

可以先记这一句：镜像决定起点，容器保留自己的改动。这句话用于当前约定的场景，不替代完整的存储模型。

刚才那题的参考解释

B 不会自动看到。A 新建文件没有改写镜像，也没有写进 B 的可写层。如果显式共享了存储，结论可能不同；那是下一节可以研究的问题。

03 / 应用换个场景，还能判断吗？

容器 A 里有你刚才新建的 note.txt。现在假设 A 被删除，随后从原来的同一个镜像重新创建容器 C。

仍然没有挂载，也没有把 A 的改动另存为新镜像。这里只做判断，不会实际删除任何东西。

C 会自带那份新建的 note.txt 吗？

不用脚本也能看的参考答案

C 不会自带那份文件。A 的可写层随容器删除，而原镜像保持不变。依据：Docker 官方的数据保留说明。

04 / 留下理解换成你自己的话

这里只供你草拟，不自动评分、不上传、不保存；刷新或关闭后会清空。想保留，请自行复制。

写完后，可以对照这句参考表达

它们用的是同一份起点，但后来各改各的。在没有共享存储时，我在 A 里加的文件不会自动进入镜像或 B。

能选对题目，不等于已经长期记住。你的解释是否真正成立，可以继续带回聊天里讨论。
