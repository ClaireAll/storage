# Storage 分类可见性设置设计

## 目标

为首页展开状态下的左侧分类栏增加可持久化的可见性设置。用户进入设置模式后可以逐项隐藏或恢复叶子分类；退出设置模式时自动保存。普通模式只显示可见分类，并在所有 Codex 子项隐藏时隐藏 Codex 分组。

## 已确认产品规则

- 侧栏展开时，在“分类”标题右侧紧邻增加 `icon-setting` 按钮，颜色使用当前主题色。
- 点击设置按钮进入编辑模式；再次点击同一按钮立即退出编辑模式并触发保存。
- 可见性只控制叶子分类。Codex 的叶子项为日报、Plugin、Skills；父分组本身不单独存储设置。
- 编辑模式中始终显示全部叶子分类，原本隐藏的项降低透明度，并使用 `icon-invisible`；可见项使用 `icon-visible`。
- 编辑模式下，分类名称和菜单本身不能导航；只有右侧眼睛按钮可操作。
- 普通模式中，隐藏项完全从左侧菜单移除。Codex 的全部子项隐藏时，Codex 父分组随之移除。
- 若当前路由的分类在退出编辑模式时被隐藏，自动导航到第一个仍可见的分类；若无可见分类，显示“请选择左侧分类”的空状态。
- 退出时立即结束编辑。保存成功不弹提示；保存失败提示错误并恢复上一次已经保存的可见性状态，不保留草稿。
- 首页顶部分类卡不再作为左侧分类可见性的控制入口，避免两个入口写入同一状态。
- 新增分类默认可见。

## 数据模型

将显示偏好存入现有每用户一行的 `theme` 表，而不是 `users` 表或新建偏好表。

```sql
alter table public.theme
  add column if not exists hidden_category_keys text[] not null default '{}'::text[];
```

- 字段名：`hidden_category_keys`。
- 类型：`text[]`，不允许为空，默认空数组。
- 数组保存稳定分类 key，例如 `{\"clothes\",\"pants\"}`，不保存路由。
- 每个可控制的叶子分类在 `homeCategories` 中定义固定 key；路由改动不会影响已保存的设置。
- 数据库 migration 必须使用 `if not exists`，以兼容已在 Supabase 控制台手动创建字段的环境。

## 方案取舍

### 推荐：扩展 theme 配置

将 `hiddenCategoryKeys` 加入 `ThemeConfig`、`ThemeDatabaseRow`、默认配置、数据库映射和 `/api/theme` 的现有读取与保存流程。该字段是用户的界面呈现偏好，且 theme 表已是当前应用的每用户偏好载体，能够复用已有的缓存、cookie 和跨设备同步能力。

### 未采用：users 表字段

`users` 负责身份与个人资料。将界面展示偏好写入该表会混合职责，并引入独立的 profile 写入链路。

### 未采用：独立偏好表

独立表适用于大量可扩展的偏好设置，但当前只有一个数组字段，会增加 API、查询和迁移复杂度，收益不足。

## 前端交互与状态

1. 初始渲染从 `initialTheme.hiddenCategoryKeys` 计算可见分类。
2. 普通模式按隐藏 key 过滤菜单叶子项；父级只在至少一个子项可见时渲染。
3. 用户点击主题色设置按钮后，创建基于已保存值的本地草稿并进入编辑模式。此时菜单显示所有叶子项，隐藏项使用低透明度样式。
4. 每个叶子项右侧显示眼睛图标按钮。点击按钮只切换草稿中的 key，不触发 `Menu` 的点击或导航。
5. 设置模式期间禁用菜单导航和名称点击，防止修改状态与路由切换互相干扰。
6. 用户再次点击设置按钮时立即退出编辑模式。前端以草稿组成完整 theme 配置并复用现有主题保存方法异步提交。
7. 保存成功后，把草稿提交为已保存状态并应用过滤规则；若当前分类被隐藏，导航到第一个可见分类或空状态。
8. 保存失败后恢复保存前的隐藏 key，保持普通模式，并显示错误信息。

## 文件边界

计划修改：

- `supabase/migrations/`：新增可重复执行的 theme 字段 migration。
- `src/app/(pages)/theme/types.ts`：扩展主题配置和数据库行类型。
- `src/app/(pages)/theme/constants.ts`：补齐默认值、解析和序列化映射。
- `src/app/utils/database.ts`：在 theme 查询字段中读取并写入该字段。
- `src/app/(pages)/home/constant.ts`：为每个叶子分类声明稳定 key。
- `src/app/(pages)/home/home-view.tsx`：持有已保存值、编辑草稿、保存和失败回退；移除顶部分类卡的可见性控制。
- `src/app/(pages)/home/home-dashboard.tsx`：渲染设置按钮、行级可见性按钮、编辑状态和菜单过滤。
- `tests/`：补充主题映射、迁移约束和侧栏状态的定向测试。

不新增接口、状态管理库或独立偏好表。现有 `/api/theme` 保持唯一保存入口。

## 错误与边界

- 未登录或主题保存失败：退出编辑模式，恢复已保存状态，并显示已有页面风格一致的错误提示。
- 主题配置中未知的隐藏 key：忽略该 key，不影响已知分类正常展示。
- 所有叶子分类隐藏：普通模式显示空状态，不保留空的 Codex 父分组。
- 后续新增叶子分类：不在隐藏数组时默认显示。
- 侧栏折叠：不显示分类标题及设置入口；进入编辑后若收起侧栏，按普通模式展示，重新展开后可再次进入设置。

## 测试与验证

- migration 包含 `text[]`、`not null`、空数组默认值和幂等列创建。
- theme 配置可以从缺失字段安全回退到空数组，并完整往返序列化 `hiddenCategoryKeys`。
- 普通模式只渲染未隐藏叶子项；全部 Codex 子项隐藏时不渲染 Codex 父分组。
- 编辑模式展示全部叶子项、正确呈现可见/隐藏图标，并阻止菜单导航。
- 保存成功后应用新过滤结果；保存失败后退出编辑、恢复已保存状态并显示错误。
- 隐藏当前分类时正确跳转到第一个可见分类；全隐藏时显示空状态。
- 顶部分类卡不再修改左侧分类可见性。
- 运行相关 Node 测试、`pnpm typecheck`、`pnpm lint` 和 `pnpm build`。

## 非目标

- 不支持用户自定义分类名称、图标、顺序或分组结构。
- 不支持分类可见性按设备、页面或时间段分别配置。
- 不调整其他主题设置、分类内容页或全局导航结构。
